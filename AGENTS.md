# AGENTS.md

Solana swap transaction parser library (Go).

## Project structure

- Library lives in `solanaswap-go/` package.
- `main.go` at root is a runnable example / manual test harness that fetches a live transaction from Solana mainnet and prints parsed swap data. Not a real CLI tool.
- Subpackages under `solanaswap-go/defi/` contain code **generated by `anchor-go`** from IDL JSON. Do not edit by hand.

## Build / verify

- `go build ./...` — builds library and `main.go` example.
- `go run main.go` — runs example against live RPC. Requires internet.
- `SOLANA_RPC_URL=<url> go test -run TestRegression ./solanaswap-go/` — **18 regression cases** that gate every change. Requires a stable RPC endpoint.
- `go vet ./solanaswap-go/` + `gofmt -l solanaswap-go/*.go` — lint/style.
- There is no CI, Makefile, linter config, or pre-commit setup.

## Plugin architecture (registry-based)

Parsing is driven by a `ProtocolParser` interface + global registry. `ParseTransaction` and
`processRouterSwaps` are thin dispatch loops — no per-protocol switch cases. Each protocol's
knowledge (program IDs, discriminator matching, parsing strategy, account-index mappings) lives
in a single `protocol_<name>.go` file.

### Adding a new protocol

Pick one of two patterns:

**A. Full `ProtocolParser` (needed for routers, aggregators, and AMMs with custom parsing):**

1. Implement `ProtocolParser` in a new `protocol_<name>.go`:
   ```go
   type myParser struct{}
   func (myParser) Name() string                  { return "MyProtocol" }
   func (myParser) ProgramIDs() []solana.PublicKey { return []solana.PublicKey{MY_PROGRAM_ID} }
   func (myParser) Kind() ParserKind              { return KindAMM } // or KindRouter, KindAggregator
   func (myParser) ParseOuter(ctx *ParseContext, outerIndex int) []SwapData { ... }
   func (myParser) ParseInner(ctx *ParseContext, outerIndex, innerIndex int, inner solana.CompiledInstruction) []SwapData { ... }
   ```
2. Call `Register(myParser{})` in `init()`.

That's it. No dispatch-switch edits. See `protocol_raydium.go` (transfer-scan AMM),
`protocol_pumpfun.go` (event + account-index hybrid), `protocol_aggregators.go` (event-based
routers) for examples.

**B. `RegisterLayout` only (simple AMMs with no custom parsing, just account-index mappings):**

1. Add a `poolLayout` entry to the `genericLayouts` table in `protocol_generic_amm.go`.
2. Or call `RegisterLayout(progID, poolLayout{...})` in `init()` from your own file.

These AMMs use the shared `resolvePoolInfo` service, which handles discriminator check,
post-balance disambiguation, and amount/decimals fill. See `protocol_generic_amm.go` for
existing entries.

### Key types

- `ProtocolParser` interface: `registry.go:28-39`
- `poolLayout` (account-index spec + discriminator whitelist): `pool_resolve.go:15-26`
- `ParseContext` (alias for `*Parser`, carries all shared state + helpers): `registry.go:10`
- `ParserKind`: `KindAMM` / `KindRouter` / `KindAggregator` — controls dispatch ordering.

### File map

| Area | Files |
|------|-------|
| Core types + registry | `registry.go` |
| Shared pool-info resolver | `pool_resolve.go` |
| Protocol parsers | `protocol_*.go` (one per family) |
| Generated anchor-go bindings | `defi/<group>/<name>/` (reference `Instruction_*` / `Event_*` / `ProgramID`) |
| Legacy process functions | `parse_transfer.go`, `parse_transfer_check.go`, `event_*.go`, `parse_manifest.go`, `parse_moonshot.go`, `parse_zerofi.go` (still used as the underlying implementations; protocol parsers delegate to them) |
| SPL transfer checks + event matchers | `checks.go` |
| Global discriminator maps | `parser.go` (`swapDiscriminator` / `addDiscriminator` / `removeDiscriminator`) — still used as fallback by `resolvePoolInfo` for protocols with no explicit whitelist |

### Dispatch flow

1. `ParseTransaction` loops outer instructions; for each, `lookupParser(progID)`.
   - `KindRouter` / `KindAggregator` → dispatched in loop 1, sets `skip=true`.
   - `KindAMM` → dispatched in loop 2 (only if no router/aggregator was found).
2. Router protocols call `ctx.processRouterSwaps` internally; that function loops inner
   instructions and dispatches each known AMM via `lookupParser` → `ParseInner`, with
   family-level dedup for parsers that implement `routerDeduper`.
3. Simple AMMs reached through a router's transfer scanner call `setTxPoolInfo`, which
   looks up `layoutRegistry` and delegates to `resolvePoolInfo`.

## Mint decimals lookup

When building `TxInfo` for event-based AMMs, **always use `p.splDecimalsMap[mint.String()]`** to get token decimals. Do NOT use `p.splTokenInfoMap[accountAddr.String()].Decimals` — the latter maps token **account addresses** to mint info, not mint addresses, and will silently return 0 (or SOL's 9 decimals) for most tokens.

## Regenerating Anchor bindings

Generated anchor-go packages live under `solanaswap-go/defi/<group>/<name>/`, each next to the
`idl.json` it was generated from (e.g. `defi/orca/orca_whirlpool/`, `defi/pumpfun/`). The package
name equals the directory name. Only IDLs that are real Anchor programs (instructions carry a
`discriminator`, and the IDL has an `address`) generate usable bindings; the rest are stubs and keep
hardcoded discriminators in the parent package.

Requires `anchor-go` (v1.x) on PATH.

```bash
# from solanaswap-go/, regenerate one package (dir name == package name):
anchor-go -idl defi/orca/orca_whirlpool/idl.json -output defi/orca/orca_whirlpool -name orca_whirlpool
rm -f defi/orca/orca_whirlpool/go.mod   # strip the per-package go.mod so it joins the parent module
```

Notes:
- anchor-go writes a stray `go.mod` into the output dir — always delete it after generating.
- If an IDL has `u128`/`i128` constants, anchor-go v1.0.0 panics. Strip the `constants` array from a
  copy of the IDL and generate from that (we only need discriminators/instructions, not constants).
  This is how `defi/meteora/meteora_dlmm` is generated.
- Reference generated discriminators from the parser as `pkg.Instruction_Xxx[:]` /
  `pkg.Event_Xxx[:]` rather than hardcoding byte arrays (see the Orca / PumpFun blocks in
  `parser.go` and `parse_transfer_check.go`).


## API usage notes

- Two constructors:
  - `NewParser(tx *rpc.GetTransactionResult)` — from RPC `GetTransaction` result.
  - `NewTransactionParser(tx *solana.Transaction, txMeta *rpc.TransactionMeta)` — from raw transaction + meta.
- Typical flow: `ParseTransaction()` -> `ProcessSwapData()`.
- `ParseTransaction()` returns a slice of `SwapData` (one per leg); `ProcessSwapData()` collapses multi-leg swaps into a single `SwapInfo`.
- Jupiter and Pumpfun have special-cased logic in `ProcessSwapData` (event-based rather than transfer-based).

## Constraints / gotchas

- Custom program swaps are **not supported** if they bypass the outer-instruction check.
- `SwapInfo.Timestamp` is not populated from the transaction (must be fetched from the block separately).
- `splTokenInfoMap` and `splDecimalsMap` are built once per parser from `tx.Meta`; logic improvements are noted in README as TODO.
- Routers that only wrap AMM calls are handled generically via `routerPrograms` + `processRouterSwaps`.
